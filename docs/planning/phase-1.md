# Phase 1 — Synthetic board prototype

> Goal (from README §11): prove the software architecture using tiny synthetic
> fixtures, plus the two licensed real boards we now hold, without depending on
> commercial repair data.
> Status: **in progress — steps 1–7 done and verified; step 8 (desktop shell) scaffolded, deps not yet installed**
> Updated: 2026-09-24

---

## 1. Phase 1 outcome

A working desktop workstation that can, on a demo/synthetic board **and** on the two
licensed boards in `data/raw/`:

1. view a board on a canvas
2. zoom and pan
3. search for a component by reference designator
4. select a component
5. view its metadata
6. show its connected net
7. highlight connected objects
8. render the schematic graph (basic)
9. navigate from board ⇄ schematic

(Measurement entry and repair notes stay in later phases; keep the canvas/search/
connectivity architecture measurement-ready.)

---

## 2. Delivery sequence (smallest safe steps)

1. **Scaffold the workspace** (`pnpm-workspace.yaml`, `tsconfig.base.json`, `package.json`,
   `.gitignore`) with packages: `domain`, `rendering`, `parsers`, `data-model`, `ui`,
   app `desktop`.
2. **Synthetic fixture** — tiny demo board (components C1, R1, U1; net VDD_DEMO;
   pads P1..P6; coordinates + layers + a couple of traces; a small interconnect graph).
   Generated by a committed script, not checked in as generated binary data.
3. **KiCad importer** (`packages/parsers`) — first real importer target. Serves the two
   licensed fixtures (one KiCad 5.1, one KiCad 9). Normalizes to the domain model.
4. **Domain model first pass** — Component, Pad, Pin, Net, Trace, Via, Layer, Board,
   BoardRevision, TestPoint, SourceReference. Unknowns are `null`, units explicit.
5. **Renderer** (`packages/rendering`) — canvas, camera-transform stack
   (board → world → camera → screen), pan/zoom, hit-testing, layer visibility,
   component + net highlighting.
6. **Search + selection** — indexed structured data (not DOM scanning).
7. **Connectivity inspection + schematic graph** — basic neighbor/whole-net traversal.
8. **Desktop shell** — Electron main/preload/renderer split, narrow preload bridge
   (AGENTS.md §17), open-project + open-boardview-file flow.
   *Scaffolded (2026-09-25): `apps/desktop` has main, preload, renderer (React), Vite config
   and narrow `board:open-boardview` IPC bridge. Dependencies are declared but **not
   installed** — `pnpm install` at the root is required before the shell can be built or run.*

## 3. Data strategy for Phase 1 (approved decision)

The licensed raw board files in `data/raw/` are large (6–7 MB each). Per AGENTS.md §18
("keep sample fixtures tiny; do not commit huge binary assets"):

- **`data/raw/` is gitignored** — the licensed fixtures are **not committed**. Provenance
  `README.md` files under `data/raw/` ARE committed (via ignore-negation) so the git
  history still documents what we hold and under what licence.
- **Provenance is code**: `scripts/fetch-licensed-fixtures.ps1` re-downloads MNT Reform
  (sourcehut, pinned commit) and OpenSFC (GitHub, pinned commit) exactly as done here,
  with expected sizes and licence URLs embedded. Anyone can reproduce `data/raw/` from
  git alone.
- **`data/samples/` holds only tiny synthetic fixtures** we author and commit
  (a few KB each). These run the base test suite with no proprietary data
  (AGENTS.md §13).
- OpenBoardData `.obdata` files: keep the two tiny iPhone 8 entries committed under
  `data/samples/` (they are ~650 B each and prove the measurement format); keep the
  larger populated ip7 example under `data/raw/` (gitignored) or regenerate via script —
  decide when the script is written.

`scripts/fetch-licensed-fixtures.ps1` must:
- fetch MNT Reform `reform2-motherboard-pcb/*` at commit
  `a85c5df98993dc0e41c840ed7d0a602639a19f1a` via sparse git clone
- fetch OpenSFC `Motherboards/SHVC-CPU-01/Rev A/*` at commit
  `6574450b1a4594b2aae436cf23869b0fb5808ce8`
- fetch OpenBoardData files (ip5/ip7 examples + iPhone 8 entries)
- print licence + provenance lines after each fetch (never silently overwrite)

## 4. What we are NOT doing in Phase 1

- No iPhone 8/Apple-specific data import (no license yet).
- No measurement capture UI or repair notes (later phases).
- No diagnosis/AI.
- No grey-market `.brd` bundling.
- No multi-device scope creep.

---

## 5. Verification

- Base test suite runs purely on synthetic fixtures (`data/samples/`).
- Render/fixture tests optionally run against `data/raw/` when present
  (skipped if absent — the repo must be testable with no licensed files).
- Coverage targets: connectivity traversal, search, pick/hit-testing, camera
  transforms, KiCad import normalization (both 5.x and 9.x sample files).
- Commands per AGENTS.md §1: never auto-run; state and then execute only when you ask.
